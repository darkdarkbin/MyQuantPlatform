# 데이터 출처와 캐시 정책

| 미국 종목/ETF 카탈로그 | Nasdaq.com 공개 시장 페이지/API 응답 | 검색 이름, 티커, 유형, 거래량 메타데이터 |
| 가격·거래량·52주 범위 | Nasdaq.com 공개 시장 페이지/API 응답 | 정적 상세 스냅샷 |

소스 URL은 각 `data/market/TICKER.json`의 `sources` 배열에도 저장된다.

## 갱신 주기

- `.github/workflows/update-market-data.yml`이 매일 정기 실행된다.
- 수동 실행 시 쉼표로 구분한 티커만 갱신할 수 있다.
- 상세 파일이 없는 티커는 앱의 생성 요청 링크를 통해 GitHub 작업으로 추가한다.
- 카탈로그와 유니버스는 상세 갱신 후 다시 계산한다.

## 거래량 100만 주 기준

각 상세 캐시에서 다음 순서로 처음 이용 가능한 값을 선택한다.

1. 최근 20거래일 평균 거래량
2. 최근 30거래일 평균 거래량
3. 공급처 평균 거래량
4. 최근 정상 거래일 거래량

카탈로그만 있는 종목은 공급처가 제공한 거래량을 `최근 정상 거래일 거래량(카탈로그 공급처 값)`으로 명시한다. 선택 값이 1,000,000주 이상이면 유니버스에 포함한다. 결과는 `data/universe.json`에 `volume`, `volumeBasis`, `meetsMillionVolume`과 함께 저장된다.

## 캐시 정책

상세 스냅샷은 다음 메타데이터를 가진다.

```json
{
  "cache": {
    "updatedAt": "ISO-8601",
    "source": "source name",
    "status": "success | stale | failed",
    "version": "2"
  },
  "dataStatus": {
    "status": "success",
    "history": "complete | short",
    "historyPoints": 0,
    "message": ""
  }
}
```

- 네트워크·파싱 실패 시 기존 정상 파일을 삭제하거나 덮어쓰지 않는다.
- 각 JSON은 독립적으로 로드되어 한 파일의 손상이 전체 앱을 중단시키지 않는다.
- 브라우저 메모리 캐시는 티커별 중복 요청을 줄인다.
- 빠른 티커 전환은 이전 요청을 취소하고 최신 요청만 렌더링한다.
- 현재 정적 배포는 디스크 격리 폴더를 별도로 만들지 않는다. 대신 빌더가 성공한 완성 스냅샷만 대상 파일에 기록하고, 검증기가 손상 파일을 배포 전에 차단한다.

## 제한과 사용 조건

- 공개 페이지의 구조나 접근 정책이 바뀌면 신규 갱신이 실패할 수 있다.
- 가격은 지연 스냅샷이며 실시간 주문·호가 데이터가 아니다.
- 무료 출처가 제공하지 않는 필드는 추정하지 않고 `정보 없음`으로 표시한다.
- 상세 캐시는 30개다. 12,339개 검색 카탈로그와 929개 유동성 유니버스 전체의 상세 데이터가 사전 생성된 것은 아니다.
- iShares/Vanguard의 데이터와 상표는 각 제공자의 이용 조건을 따른다. 저장소는 공개 페이지를 출처와 함께 참조하며 재판매용 데이터 피드를 제공하지 않는다.
